# Frozen direct-inference procedure v1

The model receives scientific task instructions and numerical test inputs, then emits actual predictions as constrained JSON. It cannot call tools, access files/network, generate an executable solution, fit a model externally or update its weights. The harness uses no model-generated code. Each task retains its native target, units and scorer; no mixed-metric universal accuracy is calculated.

The primary zero-shot condition contains no training labels. If prepared, the eight-example condition uses uniformly spaced training indices selected without examining their labels or model performance. These are in-context examples, not weight updates. Compare the conditions separately. Specialists may have undergone substantial prior task-specific training; this practical comparison does not imply equal learning budgets.

Inputs use full Python JSON floating-point representations, not rounded features or selected summary statistics. Nonfinite inputs become JSON null. IDs are local row positions, not specimen IDs or source filenames. Label meanings and the original feature names are supplied. Test targets are not loaded during prompt construction. A model receives no score feedback. Requests are sealed by SHA256, and numerical prompts remain outside Git to respect source-data redistribution restrictions.

The initial four tasks use their previously frozen custom input/split/scorer contracts as an explicitly authorized fallback. This does not convert them into official published benchmarks. Full retained test sets are queued; a partial batch is a pilot/partial result, never a completed benchmark. Official restoration and specialist-score matching remain independent admission work. Candidate sources in the 30-task map are leads, not verified winners. Exact matching requires compatible evaluation cases, inputs, targets, metric and aggregation; published scores from other settings stay contextual.

Execution follows the [routing amendment](execution-routing.md). GPT-4.1 and GPT-5 use the API; GPT-5.6 Sol and GPT-6.1 Sol use the ChatGPT-authenticated Codex CLI. The same frozen scientific prompt, prediction schema and batch membership are retained. API reasoning effort is medium with an 8192-token output ceiling for GPT-5; GPT-4.1 uses 2048 tokens and no reasoning parameter. Codex uses medium reasoning and its default output budget. These limits differ and must be disclosed. The harness also adds its own instructions, so transport and model generation are confounded. Provider-reported model identity remains unavailable where the CLI does not expose it.

Codex runs in a fresh ephemeral session with an empty working directory, read-only sandbox and tools prohibited; its event trace is checked and any tool invocation invalidates a batch. Shell, apps, browser, computer use and memories are disabled, and web search is disabled. A requested model name is not an independently verified returned model snapshot. No prediction output is executed as code.

The original four-model API pilot was superseded for Sol: its prediction responses, attempts and scores have been removed from the current study tree, and the prior two complete tasks were rerun in the harness. Usage receipts remain for spending accounting. The original API bridge was stopped, clearing its in-memory credential. The updated bridge permits API calls only for GPT-4.1 and GPT-5 and resumes historical spending accounting against the user-approved $20 total ceiling. Infrastructure failures are retained; there are no silent retries. Frozen request digests still restrict what can be dispatched.

After raw responses are saved, the scorer validates exact expected row IDs, finite values, class labels/probability bounds and completeness. Malformed, refused, truncated or missing outputs remain failures; they are not replaced with predictions. Full-case numerical scores are reported only when complete. Partial coverage is reported separately with its denominator and cannot be compared with a full-test published number. Grouped metrics retain source donor/mouse weighting. Uncertainty, when calculated, uses scientific groups rather than independent frame/spot assumptions.

The older code-generation study remains intact. No model score, specialist prediction, fitted model or manually repaired generated program from it is a direct-inference measurement.

## Pilot stopping point

The user reduced scope to approximately10–15 benchmarks. The retained pilot admits11 tasks across8 broad categories, with10 complete four-model panels and one calcium task with an incomplete GPT-5 and GPT-6.1 Sol panels. Nineteen inherited candidates are deferred from this pilot; their resource/interface dispositions are not empirical model failures. No additional tasks are added at this stopping point.

## Reasoning and output recoveries

The final per-panel configuration is in primary-summary.json and each task run-report. L04 uses64 uniformly spaced training examples as a separate in-context condition, with low reasoning for all reasoning models. GPT-5 M01 uses valid low-effort64-case batches and low-effort16-case repairs without overlap. D02 GPT-5 is fully rerun at low effort. C06 timed-out Sol cases receive recorded low-effort recovery. This is an adaptive completion workflow, not an equal-reasoning controlled model comparison. Failed and superseded valid outputs remain distinguishable in audit records.
